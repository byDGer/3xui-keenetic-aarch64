# 3x-ui для Keenetic (aarch64) одной командой

Скрипт автоматической установки веб-панели [3x-ui](https://github.com/MHSanaei/3x-ui) (панель управления Xray) на роутеры **Keenetic с архитектурой aarch64** через **Entware**.

Вы запускаете одну команду по SSH. Скрипт предлагает выбор: **автоматическая установка** (он сам ставит зависимости, скачивает **последнюю** версию 3x-ui, создаёт самоподписанный сертификат RSA 4096 — панель сразу работает по **HTTPS**, — задаёт случайные логин и пароль, включает автозапуск и в конце показывает адрес, логин и пароль) или **самостоятельная настройка** (обычное меню, где вы настраиваете каждый пункт сами).

Подробнее о выборе: [Режимы установки](#режимы-установки).

```sh
curl -fsSL https://raw.githubusercontent.com/byDGer/3xui-keenetic-aarch64/main/install-3xui-keenetic.sh | sh
```

## Что делает скрипт

Установщик `install-3xui-keenetic.sh` проверяет окружение и запускает управляющий скрипт `x-ui.sh` в режиме автоматической установки. Дальше `x-ui.sh` делает следующее:

1. Проверяет, что вы root, что установлен Entware и что роутер на **aarch64**.
2. Устанавливает через `opkg` нужные пакеты (`curl`, `wget-ssl`, `ca-certificates`, `sqlite3-cli`, `jq`, `openssl-util` и др.).
3. Определяет **последний релиз** 3x-ui на GitHub и скачивает сборку для вашего процессора (`x-ui-linux-arm64.tar.gz`).
4. Задаёт **случайные** логин, пароль и путь к панели вместо стандартных `admin / 12345`.
5. **До первого запуска** создаёт самоподписанный сертификат RSA 4096 (для IP-адреса роутера в локальной сети), применяет его к панели и проверяет, что панель действительно отвечает по HTTPS.
6. Включает автозапуск при загрузке роутера, запускает панель и выводит адрес, логин и пароль.

Панель всегда скачивается из официального репозитория [MHSanaei/3x-ui](https://github.com/MHSanaei/3x-ui). Автоматическая установка ставит только последнюю версию. Конкретную версию можно поставить вручную (пункт «Установить свою версию» в меню).

## Режимы установки

Когда вы запускаете `x-ui.sh` вручную и панель ещё не установлена, в самом начале показывается выбор:

| Режим | Что происходит |
|---|---|
| **1. Автоматическая установка** | Всё делается без вопросов (шаги выше). В конце вы получаете адрес, логин и пароль |
| **2. Самостоятельная настройка** | Открывается обычное меню: вы сами выбираете, что ставить и как настраивать (порт, путь, логин, пароль, сертификат). Перед первым запуском панели скрипт предложит создать самоподписанный сертификат и включить HTTPS (по умолчанию «да») |

Команда из раздела «Установка» (`curl ... | sh`) запускает `x-ui.sh`, и на экране сразу появляется этот выбор. Чтобы пропустить выбор и сразу выполнить автоматическую установку, добавьте `sh -s -- auto`:

```sh
curl -fsSL https://raw.githubusercontent.com/byDGer/3xui-keenetic-aarch64/main/install-3xui-keenetic.sh | sh -s -- auto
```

Если терминала нет (например, запуск из планировщика), автоматическая установка включается сама. Режим 2 можно открыть и вручную:

```sh
curl -fsSL -o /opt/tmp/x-ui.sh https://raw.githubusercontent.com/byDGer/3xui-keenetic-aarch64/main/x-ui.sh
bash /opt/tmp/x-ui.sh
```

Когда панель уже установлена, выбор не показывается: команда `x-ui` сразу открывает меню управления.

## Требования

| Что нужно | Подробности |
|---|---|
| Роутер Keenetic на **aarch64** | Проверка: `uname -m` должен вывести `aarch64` |
| Установленный **Entware** | В KeeneticOS включён компонент «Поддержка открытых пакетов» (OPKG), на старых моделях нужен USB-накопитель |
| SSH-доступ к Entware | Обычно `ssh root@192.168.1.1 -p 222` (адрес и порт могут отличаться) |
| Права root | Входите под `root` в Entware |
| Интернет на роутере | Нужен доступ к `github.com` и `raw.githubusercontent.com` |

### Роутеры на MIPS не поддерживаются

Часть моделей Keenetic построена на процессорах **MIPS** (`uname -m` выводит `mips` или `mipsel`). Для 3x-ui нет сборок под MIPS, поэтому на таких роутерах панель не заработает, и скрипт остановится с сообщением об этом. Вместо панели можно использовать Xray без веб-интерфейса, например проект XKeen.

## Установка

**1. Подключитесь к роутеру по SSH** в Entware (не в «родную» консоль KeeneticOS).

**2. Убедитесь, что есть `curl` и сертификаты** (если уже стоят, шаг можно пропустить):

```sh
opkg update && opkg install curl ca-certificates
```

**3. Запустите установку:**

```sh
curl -fsSL https://raw.githubusercontent.com/byDGer/3xui-keenetic-aarch64/main/install-3xui-keenetic.sh | sh
```

Если не хотите выполнять скрипт «вслепую», сначала скачайте его, прочитайте и только потом запустите:

```sh
curl -fsSL -o install-3xui-keenetic.sh https://raw.githubusercontent.com/byDGer/3xui-keenetic-aarch64/main/install-3xui-keenetic.sh
less install-3xui-keenetic.sh
sh install-3xui-keenetic.sh
```

## После установки

В конце установки скрипт выведет блок такого вида:

```
###############################################
x-ui установлена и запущена.
Адрес:  https://192.168.1.1:2053/aBcDeFgHiJ/
Логин:  xxxxxxxx
Пароль: xxxxxxxxxxxxxxxx
###############################################
```

- **Сохраните логин и пароль сразу:** повторно скрипт их не показывает (при необходимости их можно сменить через меню `x-ui`).
- По умолчанию панель слушает порт **2053** и доступна **только из локальной сети** (адрес интерфейса `br0`).
- Откройте адрес в браузере с устройства, подключённого к роутеру, и войдите с выданными данными.
- Браузер предупредит о **самоподписанном сертификате**: это нормально, продолжите открытие страницы. Чтобы предупреждения не было, получите настоящий сертификат для своего домена (пункт 13, см. ниже).

## Управление панелью

После установки появляется команда `x-ui`. Без аргументов она открывает интерактивное меню (запуск, остановка, смена логина и пароля, порта, SSL, резервные копии, обновление и т. д.).

Основные команды можно вызывать напрямую:

| Команда | Действие |
|---|---|
| `x-ui` | Открыть меню |
| `x-ui start` | Запустить панель |
| `x-ui stop` | Остановить панель |
| `x-ui restart` | Перезапустить панель |
| `x-ui status` | Показать состояние |
| `x-ui enable` | Включить автозапуск |
| `x-ui disable` | Выключить автозапуск |
| `x-ui update` | Меню обновления: всё сразу, только скрипт, только панель, только XRay |
| `x-ui update_xray` | Обновить только ядро Xray до последней версии |
| `x-ui update_xray_custom` | Установить выбранную версию Xray (в том числе более старую) |
| `x-ui rollback_xray` | Вернуть прежнюю версию Xray (откат) |
| `x-ui update --check` | Только проверить наличие новых версий (коды выхода 0, 10, 2: см. «Команды для мониторинга и cron») |
| `x-ui status --json` | Состояние панели в формате JSON |
| `x-ui ssl_domain` | Получить SSL-сертификат для своего домена (Let's Encrypt) |
| `x-ui ssl_remove` | Удалить SSL-сертификат из панели и вернуться к HTTP |
| `x-ui doctor` | Диагностика установки |
| `x-ui remote_access` | Мастер доступа к панели из интернета |
| `x-ui backup_auto` | Сразу сделать автоматическую копию базы данных |
| `x-ui backup_cron` | Включить или выключить копии базы по расписанию |
| `x-ui uninstall` | Удалить панель |

## Точки статуса версий

В шапке главного меню `x-ui` справа от версий **скрипта**, **панели** и **XRay** стоит цветная точка:

| Точка | Значение |
|---|---|
| зелёная ● | Стоит самая свежая версия |
| жёлтая ● | Доступно обновление (откройте «Проверка обновлений») |
| красная ● | Проверить не удалось: нет интернета, GitHub не отвечает или версия не определена |

Последние версии берутся с GitHub: скрипт из этого репозитория (ветка `main`), панель из [MHSanaei/3x-ui](https://github.com/MHSanaei/3x-ui), Xray из [XTLS/Xray-core](https://github.com/XTLS/Xray-core). Три запроса идут одновременно, у каждого есть ограничение по времени, а результат кэшируется на 30 минут (если проверка не удалась, повтор через минуту), поэтому меню открывается быстро. Точки показываются, когда панель установлена.

Чтобы меню вообще не обращалось к GitHub, поставьте в файле настроек `/opt/etc/x-ui/config/settings` строку `CHECK_UPDATES="false"` (открыть файл можно из меню: «Управление настройками» → «Редактировать файл настроек вручную»). Тогда точки не показываются, а сами пункты обновления продолжают работать.

**Другие строки шапки.** Под версиями меню показывает адрес панели (`https://…`, если сертификат работает), состояние SSL-сертификата и сколько дней он ещё действует (зелёная точка — больше 30 дней, жёлтая — 30 дней и меньше, красная — истёк или файлов нет). Если время на роутере явно неверное (год раньше 2025), выводится красное предупреждение: с неверным временем не работают HTTPS и выпуск сертификатов.

## Версия и обновление Xray

**Какая версия стоит.** В шапке главного меню `x-ui`, под строкой «Панель X-UI», показывается строка «Версия XRay: x.x.x». Версия читается из самого файла ядра при каждом открытии меню, поэтому она всегда актуальна (в том числе после обновления Xray из веб-интерфейса панели). Если ядро не найдено или не запускается, там будет «не определена».

**Как обновить только Xray.** Меню `x-ui` → «Проверка обновлений» → пункт 5 «Обновить только XRay» (или командой `x-ui update_xray`). Скрипт:

1. сравнивает установленную версию с последней на [XTLS/Xray-core](https://github.com/XTLS/Xray-core) и показывает обе;
2. скачивает архив ядра для вашего процессора (для aarch64 это `Xray-linux-arm64-v8a.zip`) и сверяет контрольную сумму SHA-256 из файла `.dgst` рядом с архивом;
3. распаковывает ядро и пробно запускает его: если оно не запускается, обновление отменяется, а старое ядро остаётся;
4. останавливает панель, заменяет файл ядра в `/opt/etc/x-ui/bin/` и запускает панель снова (если она работала);
5. сохраняет предыдущее ядро рядом как `xray-linux-arm64.bak`: если новая версия Xray вас не устроила, остановите панель, верните файл на место (`mv xray-linux-arm64.bak xray-linux-arm64`) и запустите панель.

Панель, настройки и клиенты не затрагиваются. Для распаковки нужна программа `unzip`: скрипт доустановит её сам. Учтите, что самая свежая версия Xray может опережать то, что поддерживает установленная версия панели 3x-ui; при проблемах верните `.bak` или обновите панель.

**Своя версия и откат.** В меню обновлений есть пункты «Установить свою версию XRay» (команда `x-ui update_xray_custom`: вы вводите номер, например `25.8.3`; подходит и для более старых версий, если новая не устроила) и «Откатить XRay» (команда `x-ui rollback_xray`). Откат меняет местами текущее ядро и сохранённое `.bak`, поэтому повторный откат возвращает всё назад. Контрольная сумма и пробный запуск проверяются при любой установке ядра.

## SSL-сертификат для своего домена

В меню `x-ui` есть три пункта для HTTPS:

| Пункт | Что делает |
|---|---|
| 12. Создать самоподписанный SSL-сертификат | Сертификат без доверенного центра. Браузер **всегда** покажет предупреждение «подключение не защищено» (это свойство любого самоподписанного сертификата), но шифрование работает. По умолчанию RSA 4096 (его принимают все браузеры; Ed25519 многие браузеры не принимают). Подходит для локальной сети |
| 13. Получить SSL-сертификат для своего домена | Настоящий бесплатный сертификат Let's Encrypt для вашего домена. Браузер ему доверяет, предупреждения нет |
| 14. Удалить SSL-сертификат | Убирает сертификат из настроек панели, и она снова работает по HTTP (адрес `http://...`). Файлы самоподписанного сертификата можно удалить заодно |

Пункт 13 можно вызвать и командой `x-ui ssl_domain`. Он спрашивает домен, проверяет условия, ставит `acme.sh` и `socat`, получает сертификат, кладёт файлы в `/opt/etc/x-ui/cert/<домен>/`, добавляет автопродление в cron и по желанию сразу применяет сертификат к панели.

**Что нужно заранее**

1. Домен указывает на внешний IP-адрес роутера. Нужен публичный («белый») адрес, за провайдерским NAT выпуск не пройдёт.
2. **Порт 80 на роутере свободен и доступен из интернета.** Let's Encrypt проверяет домен запросом по HTTP на порт 80. Если на нём работает веб-интерфейс роутера, перенесите его на другой порт.
3. В межсетевом экране роутера разрешён входящий TCP-порт 80 (хотя бы на время выпуска и продления).
4. Для автопродления нужен установленный и запущенный `cron` (в Entware обычно `opkg install cron`). Сертификат действует 90 дней. Без cron повторяйте пункт 13 примерно раз в 60 дней.

**После выпуска.** По умолчанию панель слушает только адрес роутера в локальной сети. Чтобы открывать её по домену из интернета, измените IP прослушивания в пункте «Изменить настройки панели» и откройте порт панели в межсетевом экране. Делайте это только с длинным паролем и осознанно: панель станет доступна всем.

Метод проверки один: HTTP на порт 80. Если порт 80 у вас недоступен, выпуск по этой схеме невозможен.

**Методы проверки домена.** При получении сертификата для домена (пункт 13) можно выбрать:

1. **HTTP на порту 80** (по умолчанию): нужны публичный IP и открытый порт 80.
2. **DNS через API вашего DNS-провайдера**: порт 80 и публичный IP не нужны (подходит, если порт 80 закрыт или роутер за NAT провайдера). Скрипт спросит код провайдера в acme.sh (например, `dns_cf` для Cloudflare) и переменные доступа к его API (например, `CF_Token=…`); список провайдеров и нужных переменных: [wiki acme.sh](https://github.com/acmesh-official/acme.sh/wiki/dnsapi). Ключи сохраняет сам acme.sh для продления и не пишутся в журнал скрипта. Вводятся они открытым текстом, поэтому не вводите их при посторонних. Метод проверен на заглушках, а не на реальных DNS-провайдерах.

Есть **тестовый режим staging**: Let's Encrypt выдаёт пробный сертификат без лимитов на число попыток, но браузеры ему не доверяют. Так удобно проверить, что всё настроено верно, а затем повторить выпуск без staging (принудительно).

## Диагностика

Пункт 21 меню или команда `x-ui doctor` проверяет установку и подсказывает, что исправить. Ничего не меняет. Проверяются: Entware и процессор, свободное место, панель (запущена ли, автозапуск, слушается ли порт), наш скрипт и команда `x-ui`, права на ключ и базу, HTTPS и срок сертификата, время роутера и его расхождение со временем GitHub, доступ к `github.com` и `raw.githubusercontent.com`, нужные программы, ядро Xray, целостность базы, cron. Итог: `✔` в порядке, `⚠` стоит обратить внимание, `✘` ошибка. Код возврата 1, если есть ошибки (`✘`).

## Доступ из интернета

По умолчанию панель слушает только адрес роутера в локальной сети. Пункт 22 меню (`x-ui remote_access`) открывает панель для доступа из интернета (слушать на всех адресах) или возвращает доступ только из локальной сети. Мастер предупреждает о рисках: без HTTPS логин и пароль пойдут по интернету открытым текстом (по умолчанию он откажется открывать панель без HTTPS). Скрипт **не может** открыть порт в межсетевом экране Keenetic: это нужно сделать самому (Сетевые правила → Межсетевой экран), мастер напоминает об этом и показывает итоговый адрес.

## Резервные копии

- Перед каждым обновлением или установкой панели скрипт автоматически делает копию базы данных (`/opt/etc/x-ui/backup/db/auto_….db.gz`).
- «Управление настройками» → «Управление резервными копиями» → «Автоматические копии по расписанию» включает копию раз в неделю (по воскресеньям в 04:30) через cron. Команда `x-ui backup_auto` делает копию сразу.
- Хранятся последние 10 автоматических копий (число меняется настройкой `BACKUP_KEEP`); ручные копии не удаляются.
- Копия делается командой `sqlite3 .backup`: это целостный снимок даже во время работы панели. Восстанавливается тем же пунктом меню, что и ручная.

Для расписания нужен установленный и запущенный `cron` (в Entware `opkg install cron`).

## Команды для мониторинга и cron

| Команда | Что делает |
|---|---|
| `x-ui status --json` | Печатает только JSON: версии скрипта, панели и Xray, `running`, `autostart`, `listen`, `port`, `path`, `https`, `cert_days_left`. Код возврата 0, если панель работает |
| `x-ui update --check` | Проверяет GitHub и печатает, где есть обновления. Коды возврата: `0` всё последнее, `10` есть обновления, `2` проверить не удалось |
| `x-ui doctor` | Диагностика; код возврата 1, если есть ошибки |

Пример задания cron, которое раз в сутки проверяет обновления: `0 9 * * * /opt/bin/x-ui update --check`.

## Безопасность

- **Не открывайте панель в интернет без необходимости.** По умолчанию она доступна только в локальной сети, и это самый безопасный вариант. Не пробрасывайте порт панели на внешний адрес без HTTPS.
- В автоматическом режиме логин, пароль и путь к панели генерируются случайно, а не стандартные `admin / 12345`. В режиме самостоятельной настройки подставляются значения по умолчанию из вопросов: задайте свои.
- Пароль не записывается в журнал скрипта.
- Для доступа извне настройте SSL-сертификат в меню `x-ui` (пункт 13, [сертификат для своего домена](#ssl-сертификат-для-своего-домена)) и используйте длинный пароль.
- Команда `curl ... | sh` выполняет скрипт с правами root. Перед запуском вы можете прочитать [`install-3xui-keenetic.sh`](https://github.com/byDGer/3xui-keenetic-aarch64/blob/main/install-3xui-keenetic.sh): он небольшой и содержит комментарии.
- Управляющий скрипт `x-ui.sh` сторонний (см. [Благодарности](#благодарности-и-ответственность)). Учитывайте это при оценке рисков.

## Обновление и удаление

**Обновление.** Повторный запуск установщика не обновляет панель: если 3x-ui уже стоит, скрипт сообщит об этом и ничего не изменит. Для обновления используйте меню:

```sh
x-ui update
```

В меню обновления (пункт «Проверка обновлений») можно обновить: всё сразу, только управляющий скрипт `x-ui.sh` (берётся из этого репозитория, ветка `main`), только панель (берётся последний релиз `MHSanaei/3x-ui`) или **только XRay** (пункт 5, см. ниже). Скрипт считается обновлённым, если в репозитории выше значение `CURRENT_VERSION_SCRIPT` в начале `x-ui.sh`.

**Восстановление.** Если панель уже установлена, команда установки из раздела «Установка» ничего не переустанавливает, а чинит управление: возвращает `/opt/etc/x-ui/x-ui.sh` из этого репозитория, пересоздаёт команду `/opt/bin/x-ui` и запускает панель, если она не работает. Это нужно, например, если после обновления панели в старых версиях появилась ошибка `/bin/bash: bad interpreter` (архив панели приносил с собой чужой `x-ui.sh`; в текущей версии скрипта это исправлено). Вручную то же делает команда:

```sh
curl -fsSL https://raw.githubusercontent.com/byDGer/3xui-keenetic-aarch64/main/x-ui.sh -o /opt/etc/x-ui/x-ui.sh && chmod +x /opt/etc/x-ui/x-ui.sh && ln -sf /opt/etc/x-ui/x-ui.sh /opt/bin/x-ui
```

**Удаление.**

```sh
x-ui uninstall
```

Перед удалением скрипт предложит сохранить резервные копии базы в `/opt/root/x-ui-backup` (по умолчанию «да») и уберёт из cron строку автопродления сертификата; каталог `/opt/etc/acme.sh` остаётся.

## Расположение файлов

| Путь | Что там |
|---|---|
| `/opt/etc/x-ui/` | Панель и управляющий скрипт |
| `/opt/etc/x-ui/db/` | База данных панели (пользователи, inbounds, настройки). Включите её в резервные копии |
| `/opt/etc/init.d/S99x-ui` | Автозапуск |
| `/opt/bin/x-ui` | Команда управления |
| `/opt/var/log/script_x-ui.log` | Журнал управляющего скрипта и установки. Когда файл вырастает больше 512 КБ, он откладывается в `script_x-ui.log.1`, и журнал начинается заново |
| `/opt/var/log/x-ui/` | Журналы самой панели |

## Настройка скрипта

Установщик настраивается переменными окружения:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `XUI_SH_URL` | `https://raw.githubusercontent.com/byDGer/3xui-keenetic-aarch64/main/x-ui.sh` | Откуда брать управляющий скрипт `x-ui.sh` |
| `XUI_SKIP_HASH` | не задана | `1` отключает проверку контрольной суммы `x-ui.sh` |

Пример с другим источником `x-ui.sh` (например, со своим форком):

```sh
curl -fsSL https://raw.githubusercontent.com/byDGer/3xui-keenetic-aarch64/main/install-3xui-keenetic.sh | XUI_SH_URL=https://example.com/x-ui.sh sh
```

Скрипт проверяет, что в таком `x-ui.sh` панель по-прежнему скачивается с `MHSanaei/3x-ui`, иначе останавливается.

### Файл настроек скрипта

Постоянные настройки лежат в `/opt/etc/x-ui/config/settings` (открыть: меню → «Управление настройками» → «Редактировать файл настроек вручную»):

| Настройка | По умолчанию | Назначение |
|---|---|---|
| `LOG_SCRIPT` | `true` | Вести журнал `/opt/var/log/script_x-ui.log` |
| `DEBUG_SCRIPT` | `false` | Показывать цепочку вызовов функций (для отладки) |
| `CHECK_UPDATES` | `true` | Проверять версии на GitHub для цветных точек; `false` — меню не обращается к сети |
| `BACKUP_KEEP` | `10` | Сколько последних автоматических копий базы хранить |

### Проверка целостности

Рядом с `x-ui.sh` в репозитории лежит файл `x-ui.sh.sha256`. Установщик и обновление скрипта из меню сверяют с ним скачанный `x-ui.sh` и отменяют установку, если сумма не совпала. Если файла нет (например, свой источник), выводится предупреждение и проверка пропускается. Сумма сверяется и при каждой загрузке файлов в репозиторий (см. `.github/workflows/check.yml`).

## Частые проблемы

| Сообщение или симптом | Причина и решение |
|---|---|
| `не найден Entware (/opt/bin/opkg)` | Entware не установлен или вы вошли не в Entware. Включите компонент OPKG, установите Entware и подключайтесь по SSH именно к нему |
| `архитектура mips…: скрипт рассчитан на aarch64` | Роутер на MIPS, сборок 3x-ui под него нет. См. [выше](#роутеры-на-mips-не-поддерживаются) |
| `нужен root` | Войдите под `root` |
| `curl: (60)` или ошибки сертификата | Установите `ca-certificates`: `opkg install ca-certificates` |
| `Не удалось получить версию x-ui, попробуйте позже` | Нет доступа к `github.com` или исчерпан лимит запросов. Проверьте интернет на роутере и повторите позже |
| `не удалось скачать x-ui` | В последнем релизе 3x-ui временно нет сборки под ваш процессор или нет доступа к `github.com`. Повторите позже или откройте [issue](https://github.com/byDGer/3xui-keenetic-aarch64/issues) |
| `в скачанном x-ui.sh нет режима auto_install` | В репозитории лежит старая версия `x-ui.sh` (нужна 1.0.3 или новее) |
| `/bin/bash: bad interpreter: No such file or directory` при запуске `x-ui` | Файл `/opt/etc/x-ui/x-ui.sh` подменён чужим скриптом (так делали старые версии при обновлении панели). Запустите команду установки ещё раз: она восстановит скрипт. Подробнее в разделе «Обновление и удаление» |
| `x-ui: not found` | В текущей оболочке нет `/opt/bin` в `PATH` (например, вы вошли в системную консоль роутера, а не в Entware). Запускайте по полному пути `/opt/bin/x-ui` или выполните `export PATH=/opt/sbin:/opt/bin:$PATH`. Если файла `/opt/bin/x-ui` нет, запустите команду установки: она создаст ссылку |
| В панели «сертификат есть», но она работает по HTTP | Пути к сертификату заданы, а самих файлов нет (панель в этом случае молча работает по HTTP). Создайте сертификат пунктом 12 или уберите настройку пунктом 14. При ручной настройке скрипт теперь сам предлагает создать недостающий сертификат |
| `контрольная сумма x-ui.sh не совпала` | Файлы в репозитории обновлены не полностью (например, загружен новый `x-ui.sh`, а `x-ui.sh.sha256` остался старым) или GitHub ещё отдаёт старую копию из кэша (подождите 5 минут). Отключить проверку для установщика: `XUI_SKIP_HASH=1` |
| Красное предупреждение про время в шапке меню | Время на роутере неверно. Включите синхронизацию времени (NTP) в настройках Keenetic |
| Браузер пишет «подключение не защищено» / «ваше подключение не является закрытым» | Для самоподписанного сертификата это нормально: нажмите «Дополнительно» → «Перейти на сайт». Чтобы предупреждения не было, получите сертификат для своего домена (пункт 13). Если HTTPS не нужен, верните HTTP (пункт 14) |
| Браузер пишет `ERR_SSL_PROTOCOL_ERROR` или страница не открывается по `https://` | Панель работает по HTTP: откройте адрес с `http://`. Включить HTTPS можно пунктом 12 |
| Браузер пишет про несовпадение имени (`ERR_CERT_COMMON_NAME_INVALID`) | Сертификат выпущен для IP-адреса роутера в локальной сети. Открывайте панель именно по этому IP либо получите сертификат для своего домена (пункт 13) |
| `HTTPS не включён: панель будет работать по HTTP` | Не удалось создать сертификат (нет `openssl`). Установите `opkg install openssl-util` и создайте сертификат в меню `x-ui` (пункт 12). Создание ключа RSA 4096 на роутере может занять до минуты |
| `не удалось скачать … x-ui.sh` | Нет доступа к `raw.githubusercontent.com` или изменился адрес файла. Проверьте, что открывается `https://raw.githubusercontent.com/byDGer/3xui-keenetic-aarch64/main/x-ui.sh` |
| `панель не установилась` | Смотрите журнал: `tail -n 50 /opt/var/log/script_x-ui.log` |
| `не удалось запустить x-ui` при старте | Если скрипт показал под ошибкой «Вывод панели при запуске», причина в этих строках (например, не найден файл сертификата). Полный вывод лежит в `/opt/var/log/x-ui-panel.out`. Если вывода нет, запустите панель вручную и смотрите ошибку: `/opt/etc/x-ui/xui run`. Проверить всё сразу: `x-ui doctor` |
| Панель не открывается | Проверьте `x-ui status`, адрес и порт, и что вы подключены к локальной сети роутера |

Сообщая о проблеме, приложите вывод скрипта и последние строки `/opt/var/log/script_x-ui.log`. **Пароли из вывода удалите.**

## Как это устроено

- **Панель** (3x-ui) берётся из релизов `MHSanaei/3x-ui`, сборка `x-ui-linux-arm64.tar.gz`, всегда последняя версия.
- **Управляющий скрипт** `x-ui.sh` лежит в этом репозитории, основан на проекте x-ui-keenetic и переведён на русский. Он умеет ставить панель в Entware, регистрировать автозапуск, создавать сертификаты и показывать меню. Свои обновления он тоже берёт из этого репозитория. Весь код снабжён подробными комментариями на русском: начните с блока в начале файла.
- **Установщик** `install-3xui-keenetic.sh` короткий: проверяет окружение, ставит минимум пакетов, скачивает `x-ui.sh` и вызывает `bash x-ui.sh auto_install`. Никаких правок скачанного скрипта он не делает.
- **Автоматический режим** внутри `x-ui.sh`: пока он включён, все вопросы получают ответы «по умолчанию», а логин, пароль и путь панели подставляются случайными.
